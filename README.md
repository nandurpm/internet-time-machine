# Internet Time Machine

**Internet Time Machine** is a local-first, endpoint-scoped network-quality historian. It creates a calm, legible record of reachability, latency, DNS lookup time, and best-effort packet loss while preserving the difference between **direct measurements**, **estimates**, and **simulated/demo data**.

> An availability incident in this application means that one monitor could not reach one configured endpoint. It is **not** presented as evidence of an internet-wide outage.

| Capability | Implementation boundary |
|---|---|
| Endpoint profiles | HTTP(S) targets, DNS hostnames, conservative 15-minute-or-longer intervals, and validated configuration. |
| Measurement adapters | Direct HTTP `HEAD` reachability/latency and DNS lookup timing. Packet-loss collection is intentionally blank until an ICMP-capable adapter is supplied. |
| Data provenance | Each metric identifies whether it is direct, estimated, or simulated. Seed data is visibly labeled simulated/demo. |
| Persistence | A separate embedded SQLite repository stores profiles, timestamped measurements, and endpoint-local incident events. |
| Historical analysis | Daily, weekly, monthly-equivalent filtered, and explicit custom-date summaries, together with latency, DNS, availability, loss, and incident visualizations. |
| Scheduling | An authenticated, platform-managed callback is created per endpoint profile. It respects the saved safe interval and does not depend on a browser tab being open. |

## Quick start

This repository uses Node.js, pnpm, React, Express, tRPC, and the built-in `node:sqlite` module. Use a Node.js 22+ runtime with SQLite support enabled. The project starts with explicitly labeled demo records so the interface can be reviewed without probing any endpoint.

```bash
pnpm install
pnpm dev
```

Open the local preview and create a profile under **Configuration**. A profile must use an HTTP(S) URL, omit embedded credentials, and select an allowed conservative interval. See [`examples/config.example.json`](examples/config.example.json) for the portable profile shape.

## Local Windows and Linux use

The repository is portable as a self-hosted Node application. After installing Node.js 22+ and pnpm, use `./run-local.sh` on Linux or `run-local.cmd` on Windows. Both commands start the application in development mode at port `3000`; pass `--port=4100` to choose a different port. For a production-like local process, run `pnpm build` followed by `pnpm start:local -- --port=4100`. Full details, including automatic free-port fallback, are in [`docs/LOCAL_RUN.md`](docs/LOCAL_RUN.md).

The managed production deployment is available at **https://timemachine-alxsadqu.manus.space**. The connected custom live domain **https://monitor.nandakumarm.dpdns.org/** was also verified on 24 August 2026: it loaded the Internet Time Machine dashboard and its explicitly labeled simulated demo data. These hosted links are optional: the local application can run without the website.

### External hosting note

The repository’s standard build emits both a Node/Express server bundle at `dist/index.js` and browser assets at `dist/public`. Deploying `dist` as a static Vercel output makes Vercel return the server bundle as JavaScript text at `/`, rather than running the dashboard. Pointing Vercel at `dist/public` alone is also not a functional full deployment because the application needs its authenticated API, SQLite-backed monitoring data, scheduler callback, and server-side AI credentials. Use the managed production URL above or the local runtime unless the application is intentionally refactored for Vercel serverless infrastructure. See [`docs/VERCEL_DEPLOYMENT.md`](docs/VERCEL_DEPLOYMENT.md) for the observed issue and a safe migration checklist.

## Data semantics

| Label | Meaning | Appropriate use |
|---|---|---|
| **Directly measured** | Observed by the configured adapter during that collection cycle. | Latency, HTTP availability, and successful DNS lookup timings. |
| **Estimated** | A value derived by an adapter rather than directly observed. | Reserved for adapters that make their method explicit. |
| **Simulated / demo** | Seeded demonstration data generated by this repository. | Interface review and walkthroughs only; never operational diagnosis. |

Download and upload testing is **opt-in**. The default adapter does not initiate a bandwidth transfer, even after opt-in, unless a dedicated adapter has been supplied. This prevents a dashboard from silently creating expensive or aggressive traffic.

## AI trend summary

The dashboard includes a user-triggered **AI trend summary** for the currently selected endpoint and date range. The server prepares a compact aggregate containing metric averages, record provenance totals, time boundaries, and endpoint-local incident counts. It intentionally excludes endpoint URLs and raw error messages. The model is asked to preserve the direct, estimated, and simulated distinction and to avoid claims about broader internet conditions or root causes.

Summaries are not generated automatically; a signed-in user explicitly selects **Generate summary**. The feature currently selects the live `gpt-5-mini` model when available and uses project AI usage for each request. Read [`docs/AI_SUMMARY.md`](docs/AI_SUMMARY.md) for the full data boundary and output contract.

## Background collection

After the site is deployed, sign in, create an active profile, and use **Enable schedule**. The scheduler creates one authenticated collection callback for the endpoint and persists the scheduler identifier against that profile. The callback looks up the profile using the authenticated job identity rather than trusting a client-supplied endpoint ID.

The supported intervals are 15, 30, 60, 120, 240, 360, 720, and 1440 minutes. These conservative defaults are intentional. The system does not use in-process timers, which are unreliable in autoscaling environments. More detail is available in [`docs/SCHEDULING.md`](docs/SCHEDULING.md).

## Validation

Run the automated suite and production checks before contributing changes.

```bash
pnpm test
pnpm check
pnpm build
```

The tests cover malformed configuration, provenance-aware statistics, endpoint-local outage detection, SQLite persistence, and recoverable measurement failures. Contribution expectations are documented in [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Safety and privacy

Configured endpoint addresses, resulting metadata, and error messages can be sensitive operational information. Keep the application access-controlled, avoid monitoring third-party systems without authorization, and do not place credentials in endpoint URLs. Read [`docs/PRIVACY_AND_SAFETY.md`](docs/PRIVACY_AND_SAFETY.md) before deployment.
